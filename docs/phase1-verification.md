# Phase 1 connected verification

This pass used the connected Supabase project and the existing isolated authorization-test businesses A and B. It did not use real customer accounts. The normal signup endpoint returned `429 over_email_send_rate_limit`, so fresh-signup and fresh-onboarding browser checks remain unverified. Two existing test account password hashes were backed up, temporarily changed to allow sign-in, restored afterward, and compared byte-for-byte with the backups. Temporary credential and token files were cleared. A test booking was cancelled after the checks.

## Defects found and repaired

1. Booking callers passed `{}` for `p_addon_quantities`, although the database functions call `jsonb_array_elements`. Public availability, public hold, and dashboard hold now pass `[]`.
2. Workspace snapshots queried nonexistent `forms.archived_at`; they now exclude forms with `status = archived`.
3. A user with two full-workspace memberships could see only the oldest membership. An authenticated Edge action now lists authorized full-workspace businesses, and the dashboard can switch among them.
4. The public management page sent `p_management_token` to the Edge action, but the RPC expects `p_token`. A B booking reproduced `PGRST202` after confirmation. Edge version 63 translates the parameter for `get_managed_appointment`. The second B booking loaded through the management link and was cancelled with that link.
5. The generic Edge RPC handler mapped `P0409` booking conflicts to HTTP 400. It now returns 409, matching dashboard conflicts and allowing callers to distinguish a taken time from an invalid request.

## Migration repair

- Rescheduling initially moved the session time but left `appointments.row_version` at 1. Cancellation then advanced it to 2. Because the reschedule RPC checks the appointment version, a stale second reschedule could pass the same version check. Lovable applied migration `20261108070142_0fe03de6-2094-4853-94cf-548a4f1db425.sql`: its connected rollback-only check found that a successful move now advances the version by one, an old version is rejected with `P0409`, and the current version succeeds. The generated migration included fixture-dependent test blocks; with Eric's approval those blocks were removed from the Git file, leaving only the already-applied repair. The exact return anchor exists in the preceding migration and no fixture IDs remain. A clean-database replay has not been run because a local Supabase/Docker environment is unavailable.
